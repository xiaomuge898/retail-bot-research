# 新型滑块缺口适配实施计划

## 目标

使用 `dev/样本.zip` 中的开发样本分析并适配新型滑块缺口，在参数冻结后用独立验证样本检查精度。整个流程只修改离线图像识别逻辑。

## 前置条件

- Python 3.12。
- 项目虚拟环境 `.venv`。
- 已安装 `requirements.txt` 中的 OpenCV 和 NumPy。
- 样本压缩包完整可读。

## 第一步：解压样本

样本不能直接从 ZIP 内运行测试。先按 [项目说明](../../项目说明.md#解压步骤) 解压；压缩包顶层目录已是 `样本/`，无需重命名。

解压后的关键结构：

```text
dev/样本/
├── 样本1/ ... 样本9/    # 140 组开发数据
└── 验证样本/             # 35 组独立回归数据
```

检查项：

- [ ] JPG 背景图共 175 张。
- [ ] PNG 小拼图共 175 张。
- [ ] 10 个样本目录均包含 `滑块真实距离.txt`。
- [ ] 不把解压后的 `dev/样本/` 提交到 Git。

## 第二步：建立基线

1. 创建并复用虚拟环境。
2. 安装项目依赖。
3. 只运行输入契约和开发样本测试。
4. 记录失败图片、期望坐标、预测坐标和绝对误差。

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m unittest dev.tests.test_captcha.InputContractTests -v
.\.venv\Scripts\python.exe -m unittest dev.tests.test_captcha.DevelopmentAccuracyTests -v
```

此阶段不要根据 `验证样本` 调整代码或参数。

## 第三步：分析新型缺口

对失败样本至少检查以下信息：

- 小拼图是否带 alpha 通道。
- 小拼图是否接近背景全高。
- 有效拼图区域和背景的相对宽度。
- 缺口是浅色填充、阴影轮廓还是纹理差异。
- JPG 压缩、缩放和强背景纹理是否破坏现有特征。

优先把失败归入现有结构分支。只有一组可复现的新结构无法被已有特征区分时，才新增候选特征或分流条件。

## 第四步：实现与开发回归

实现顺序：

1. 补充能稳定复现失败的开发样本。
2. 修改 `CAPTCHA.py` 中最接近根因的共享方法。
3. 保持公共接口参数和返回类型不变。
4. 运行输入契约、候选聚类和全部开发样本测试。
5. 删除按文件名、图片编号或固定答案返回坐标的特例。

完成条件：

- [ ] 所有输入类型行为一致。
- [ ] 全部开发样本逐组误差不超过 3 px。
- [ ] 无效输入仍明确抛出 `ValueError`。
- [ ] 没有新增非必要生产依赖。

## 第五步：冻结参数并验证

开发回归通过后冻结阈值和权重，再运行验证测试：

```powershell
.\.venv\Scripts\python.exe -m unittest dev.tests.test_captcha.ValidationAccuracyTests -v
```

验证报告至少包含：

- 样本编号。
- 期望横坐标。
- 预测横坐标。
- 绝对误差。
- 总通过数、最大绝对误差和平均绝对误差。

如果验证失败，只记录和归因失败案例。需要继续开发时，应把失败类型纳入开发集，并准备一批新的、未参与调参的验证样本。

## 第六步：完整反向验证

```powershell
.\.venv\Scripts\python.exe -m py_compile CAPTCHA.py dev\tests\test_captcha.py
.\.venv\Scripts\python.exe -m unittest discover -s dev\tests -v
git diff --check
git status --short
```

发布前检查：

- [ ] README 明确说明样本 ZIP 必须先解压。
- [ ] 目录树与仓库实际结构一致。
- [ ] 所有命令只使用相对路径。
- [ ] 文档不含账号、邮箱、令牌、代理、本机用户名或绝对路径。
- [ ] `.venv/`、缓存和 `dev/样本/` 未进入提交。
- [ ] 变更提交在功能分支，不直接提交到主分支。

## 风险与替代方案

- **风险**：新增规则只改善一小类图片并破坏旧样本。**处理**：每次修改都运行全部开发回归，冻结后再运行验证集。
- **风险**：规则分支随类型增加而持续膨胀。**替代方案**：样本量和标注质量足够时，改用轻量目标检测模型。
- **风险**：页面显示尺寸与原图不同。**替代方案**：由调用方按 `显示宽度 / 原图宽度` 换算，识别器保持原图坐标语义。
